# 모델링 평가지표 정리 — 1차 · 2차 · 3차

`Machine failure`(0=정상, 1=불량) 이진분류를 세 번(`model_1.ipynb` → `model_2.ipynb` → `model_3.ipynb`)
다시 짜면서 나온 학습·평가 결과를 지표 중심으로 모아 둔 문서입니다. 서술형 진행 보고서는
[`1차.md`](1차.md) / [`2차.md`](2차.md) / [`3차.md`](3차.md), 3차 EDA·피처 상세는
[`modeling2_binary_eda.md`](modeling2_binary_eda.md)를 참고하세요.

- **공통 조건**: `ai4i2020.csv` 10,000행, train/test = 8:2, `stratify=y`, `random_state=42`(2차 일부 49)
- **핵심 지표**: 클래스 불균형(불량 3.39%)이 심해 정확도(accuracy)는 참고용이고, **불량(1) 클래스의
  정밀도 / 재현율 / F1-score**와 **ROC-AUC**를 기준으로 본다.
- 표의 수치는 재실행 시 랜덤성으로 소수점 아래에서 소폭 달라질 수 있다.

## 1차 — Baseline (`src/model_1.ipynb`)

**전처리**: `Product ID` 제거 · `Type` 원-핫 인코딩 · `MinMaxScaler` 정규화 · `SMOTE`로 불량 클래스
오버샘플링(Random Forest 학습에만 적용) · **파생변수 없이 원본 변수만 사용**

**모델 구성**

| 모델 | 주요 설정 |
| --- | --- |
| Random Forest | `n_estimators=500`, `max_depth=15`, `min_samples_leaf=2`, `class_weight="balanced"`, SMOTE 적용, 예측 임계값 **0.3**(재현율 우선) |
| XGBoost | `n_estimators=300`, `learning_rate=0.05`, `max_depth=5`, 임계값 0.5, 원본 학습 데이터 |
| LightGBM | `n_estimators=300`, 임계값 0.5, 원본 학습 데이터 |

**성능 (불량(1) 클래스 기준)**

| 모델 | 정확도 | 정밀도 | 재현율 | F1-score |
| --- | ---: | ---: | ---: | ---: |
| Random Forest (임계값 0.3 + SMOTE) | 0.942 | 0.35 | **0.85** | 0.50 |
| XGBoost | 0.984 | **0.91** | 0.59 | 0.71 |
| LightGBM | **0.985** | 0.89 | 0.62 | **0.73** |

**혼동행렬 (테스트 2,000건)**

| 모델 | 정상→정상 | 정상→불량(오탐) | 불량→정상(누락) | 불량→불량(정탐) |
| --- | ---: | ---: | ---: | ---: |
| Random Forest + SMOTE | 1,833 | 99 | 10 | **58** |
| XGBoost | 1,925 | **7** | 28 | 40 |
| LightGBM | **1,927** | **5** | 26 | 42 |

**결론**: 정확도만 보면 셋 다 94~98%로 좋아 보이지만, "전부 정상"이라 찍어도 96.6%가 나오는
데이터라 착시다. RF는 임계값을 낮춰 재현율 0.85를 얻었으나 정밀도 0.35(오탐 99건), 반대로
XGBoost/LightGBM은 정밀도 0.9대지만 재현율 0.6 전후로 실제 불량의 약 40%를 놓친다.
→ **원본 변수만으로는 정밀도와 재현율을 동시에 잡는 모델이 없다.**

## 2차 — 피처 엔지니어링 + 하이퍼파라미터 튜닝 (`src/model_2.ipynb`)

**추가한 파생변수 7개**: `Power`(회전속도×토크), `Temp_diff`(공정온도−기온), `Power_wear`(동력×공구마모),
`Torque_per_RPM`, `Torque_wear`(토크×공구마모), `Temp_Torque`(온도차×토크), `Temp_ratio`(공정온도/기온)

**튜닝**: `RandomForestClassifier` + `RandomizedSearchCV`
- `n_iter=30`, `cv=5`, **`scoring="recall"`** (재현율을 목적함수로 직접 최적화)
- 탐색 공간: `n_estimators [100,200,300,500]`, `max_depth [5,10,15,20,None]`,
  `min_samples_split [2,5,10]`, `min_samples_leaf [1,2,4]`, `max_features ["sqrt","log2"]`,
  `class_weight ["balanced", {0:1,1:3}, {0:1,1:5}, {0:1,1:8}]`
- **선택된 파라미터**: `n_estimators=300`, `min_samples_split=5`, `min_samples_leaf=2`,
  `max_features="log2"`, `max_depth=None`, `class_weight={0:1, 1:8}`
- 교차검증 재현율(best score): **0.995**

**성능 (불량(1) 클래스 기준) — 1차 RF와 비교**

| 모델 | 정확도 | 정밀도 | 재현율 | F1-score |
| --- | ---: | ---: | ---: | ---: |
| 1차 Random Forest (임계값 0.3) | 0.942 | 0.35 | 0.85 | 0.50 |
| 2차 Random Forest (RandomizedSearchCV 튜닝) | 0.940 | 0.34 | **0.91** | 0.50 |

**결론**: 재현율은 0.85 → 0.91로 올랐지만(교차검증 0.995와는 큰 차이 — 테스트셋에서는 그만큼 안 나옴),
**정밀도는 0.34로 더 떨어졌고 F1은 0.50으로 사실상 1차와 동일**하다.
→ **재현율 한 축만 튜닝하면 정밀도를 그만큼 깎을 뿐, 정밀도–재현율 트레이드오프 자체는 풀리지 않는다.**
파생변수를 7개 늘리고 탐색을 정교하게 해도 "모델이 스스로 좋은 경계를 찾게 맡기는" 접근의 한계.

## 3차 — 위험구간(risk_zone) 피처 (`src/model_3.ipynb`, 최종 배포)

**접근 전환**: 모델이 규칙을 스스로 찾게 두지 않고, **UCI AI4I 2020 공식 문서에 정의된 세부 고장
판정 임계값**을 원본 입력 변수만으로 다시 계산해 피처로 주입(라벨을 직접 쓰는 게 아니므로 데이터
누수 아님).

| 피처 | 점등(=1) 조건 | 의미 |
| --- | --- | --- |
| `hdf_zone` | 온도차 < 8.6K **AND** 회전속도 < 1380rpm | 방열 고장 위험 |
| `pwf_zone` | 동력 < 3500W **OR** 동력 > 9000W | 전력 고장 위험 |
| `osf_zone` | 토크×공구마모 > Type별 임계값(L 11000 / M 12000 / H 13000) | 과부하 위험 |
| `high_wear` | 공구마모 > 200분 | 공구마모 고장 임박 |
| `risk_zone_count` | 위 4개 합산(0~4) | 위험 신호 동시 점등 개수 |

**신호 강도 검증**
- `risk_zone_count` ↔ `machine_failure` 상관계수 **0.630** — 원본 변수 중 최고인 `torque`(0.191)의 약 3배
- `risk_zone_count`별 실제 불량률: **0개 → 0.11% / 1개 → 27.23% / 2개 이상 → 100%**

**피처셋 정의**
- **Baseline**: `Type`(원-핫 2개) + `air_temp` / `process_temp` / `rotational_speed` / `torque` / `tool_wear` (총 7개)
- **Enhanced**: Baseline + `temp_diff` / `machanical_power` / `tool_stress` +
  `hdf_zone` / `pwf_zone` / `osf_zone` / `high_wear` / `risk_zone_count` (총 15개)
- 불균형 보정: Random Forest / LightGBM은 `class_weight="balanced"`, XGBoost는 `scale_pos_weight`

**성능 — 모델 3종 × 피처셋 2종 (불량(1) 클래스 기준, `random_state=42`)**

| 모델 | 피처셋 | 정확도 | 정밀도 | 재현율 | F1-score | AUC |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Random Forest | Baseline | 0.982 | 0.750 | 0.706 | 0.727 | 0.970 |
| XGBoost | Baseline | 0.984 | 0.761 | 0.750 | 0.756 | 0.970 |
| LightGBM | Baseline | 0.987 | 0.839 | 0.765 | **0.800** | 0.971 |
| **Random Forest** | **Enhanced** | **0.994** | **1.000** | 0.838 | **0.912** | 0.973 |
| XGBoost | Enhanced | 0.992 | 0.934 | 0.838 | 0.884 | 0.973 |
| LightGBM | Enhanced | 0.994 | 0.966 | 0.838 | 0.898 | **0.974** |

**결론**
- **zone 피처 효과는 3개 모델 전부에서 재현**된다 — F1 상승폭 Random Forest **+0.185**, XGBoost +0.128,
  LightGBM +0.098. 특정 알고리즘에 대한 과적합이 아님.
- Baseline만 보면 LightGBM(F1 0.800)이 최고지만, Enhanced에서는 **Random Forest(F1 0.912)가 역전** —
  원래 조합 규칙 탐지력이 약했던 모델이 위험구간 피처 효과를 가장 크게 흡수.
- 재현율 0.838은 Enhanced 3개 모델이 정확히 동일(`risk_zone_count>=2`면 불량률 100%인 규칙이 워낙
  강해서 확실한 불량 샘플은 어느 모델이든 똑같이 잡음). 정밀도만 RF 1.000 > LightGBM 0.966 > XGBoost
  0.934로 갈림.
- AUC는 6개 조합 전부 0.970~0.974로 거의 동일 — zone 피처는 "순위 매기기(AUC)"보다 "임계값 근처
  정확한 판별(precision/recall/F1)"에 기여.
- **최종 채택: Random Forest (Enhanced)** → `model/random_forest_enhanced.joblib`
  (`{"model", "features"(15개 순서), "metrics"}` 한 파일로 저장, UI가 지표의 단일 출처로 사용)

## 1차 → 2차 → 3차 한눈에 비교

매 단계에서 가장 좋았던 조합 (불량(1) 클래스 기준):

| 단계 | 접근 | 정밀도 | 재현율 | F1-score |
| --- | --- | ---: | ---: | ---: |
| 1차 | Baseline + 예측 임계값 0.3 (Random Forest) | 0.35 | **0.85** | 0.50 |
| 2차 | 파생변수 7개 + `RandomizedSearchCV` 재현율 튜닝 (Random Forest) | 0.34 | **0.91** | 0.50 |
| 3차 | 위험구간(risk_zone) 피처 + Random Forest (Enhanced) | **1.000** | 0.838 | **0.912** |

- 1차·2차는 모델/파라미터/파생변수를 아무리 바꿔도 **F1이 0.50 언저리에 고정**됐다.
- 3차에서 **도메인 지식(공식 고장 판정 규칙)을 피처로 직접 주입**하자 F1이 0.50 → **0.912**로 뛰었다.
- 교훈: "더 정교한 튜닝"보다 "데이터에 이미 있는 물리 규칙을 모델이 알아채기 쉬운 형태로 바꿔주는 것"이
  훨씬 효과적이었다. 불균형 데이터에서는 AUC 하나로 개선폭을 판단하지 말고 F1 / 정밀도 / 재현율을 함께 봐야 한다.
